Next.js Application Guide

How the Harmoni.AI landing page is structured, what npm run build produces, how routing and server-side rendering work, and what to move to a server.

1. Overview

This project is a Next.js 16 App Router application written in React 19. It is the Sonata Harmoni.AI marketing landing page: one page made of stacked, animated sections (Navbar, Hero, Product Stack, Testimonials, …, Footer).

The home page is configured for Server-Side Rendering (SSR) on every request. The server produces complete HTML for each visit; the browser then loads JavaScript to hydrate that HTML and run the Framer Motion animations.

Browser requests /→ Node server renders React to HTML→ HTML sent (content visible immediately)→ JS bundles load & hydrate→ Animations / interactivity active

Server vs Client Components

  • layout.jsx and page.jsx are Server Components (default): they run only on the server.
  • Each section starts with 'use client' because it uses Framer Motion, hooks, or browser APIs. Client Components are still server-rendered for the first HTML, then hydrated in the browser.
  • Browser-only code (window, matchMedia, document) is kept inside useEffect or useSyncExternalStore so it never runs during server rendering.

4. Routing structure

App Router uses folder-based routing: the folder path under src/app/ is the URL, and a page.jsx file makes it publicly reachable.

URLSourceNotes
/src/app/page.jsxThe only page. Dynamic (SSR on every request).
any other URLbuilt-in _not-foundAuto-generated 404 (static HTML).

One route, many sections. The "pages" visitors see (Hero, Industries, Testimonials …) are scroll sections inside /, not separate URLs.

Special files

FileRole
layout.jsxWraps all pages. Persistent across navigation. Defines <html>/<body>, global CSS and metadata (title, description, icon) and viewport.
page.jsxThe UI for a route.
route.js(not used yet) An API endpoint, e.g. src/app/api/contact/route.js → /api/contact.
loading.jsx / error.jsx / not-found.jsx(not used yet) Optional per-route loading, error, and 404 UI.

5. Rendering: static vs SSR

By default Next.js prerenders a page with no dynamic data at build time (static, shown as ○ in build output). That page is still server-rendered HTML, but generated once. We changed this in src/app/page.jsx:

export const dynamic = 'force-dynamic'

Now the page is rendered on every request (shown as ƒ in build output).

Static (○)Dynamic SSR (ƒ) — current
RenderedOnce, at buildOn every request
Response headersCacheable by CDNCache-Control: no-store
Speed / costFastest, cheapestUses server CPU per visit
Per-request data (cookies, headers, live API)NoYes
HostingAny static host possibleNeeds a Node.js server (or Vercel etc.)

Trade-off to be aware of: the page currently has no per-request data, so force-dynamic adds server load without changing the output. Keep it if you plan to read cookies/headers or fetch live Drupal API data. Otherwise remove the line to get fast prerendering, or use export const revalidate = 60 to regenerate every 60 seconds (ISR).

Hydration and the mobile hook

The server cannot know the visitor's screen size. useIsMobile (src/components/useIsMobile.js) uses useSyncExternalStore with false as the server value, so the server always renders desktop markup and the client switches to the real value during hydration — without a hydration-mismatch error.

7. The .next/ folder

.next/ is a single, self-contained build artifact that holds the compiled app, the lookup tables the server needs, and some caches and debug data. It is fully regenerated by npm run build and is git-ignored. Never edit it by hand.

Folders

PathWhat it containsNeeded at runtime?
server/Compiled server code: server/app/page.js (your home page), server/chunks/ (shared code such as React, Next and your components), prebuilt _not-found and _global-error pages.Yes
static/Files sent to the browser: static/chunks/ (JS bundles for hydration and animations) and static/media/ (fingerprinted font files). Served under /_next/static/…Yes
cache/Build cache (compile results, image-optimization output). Speeds up the next build; can also hold runtime fetch/ISR cache.No safe to delete
diagnostics/Small JSON files with build info and warnings, for debugging/telemetry.No

trace, trace-build, turbopack/Build performance traces and Turbopack's internal state.No
dev/Output of npm run dev, separate from the production build.No

Size reference (this project): .next/ ≈ 68 MB, public/ ≈ 18 MB, node_modules/ ≈ 456 MB.

9. Deploying to a server

Option A — Standard Node server

Copy to the server

  • .next/ (build output)
  • public/
  • package.json and package-lock.json
  • next.config.mjs
  • Environment variables / .env.local (if any)

Do not copy

  • node_modules/ (install fresh on the target)
  • src/ (not needed to run; keep it in git)
  • .next/cache, .next/dev, .next/diagnostics, .next/types, .next/trace* (optional to skip)
# on the server (Node ≥ 20.9)
npm ci --omit=dev          # install production dependencies only
npm start                  # or: npx next start -p 80

Alternatively, copy the source (without node_modules and .next) and run npm ci && npm run build && npm start on the server itself. This ensures the build happens on the same OS and Node version as production.

Option B — Standalone output (best for Docker)

Add this to next.config.mjs:

const nextConfig = {
  reactStrictMode: true,
  output: 'standalone',
}

The build then creates .next/standalone/, a minimal folder containing only the dependencies actually needed. You must also copy the static assets next to it:

cp -r public .next/standalone/public
cp -r .next/static .next/standalone/.next/static
node .next/standalone/server.js        # PORT=3000 HOSTNAME=0.0.0.0 by default

Option C — Vercel

Push the repo to Git and import it in Vercel. It runs the build and hosting for you. No server setup, and the SSR page runs as a serverless function.

Running in production

  • Keep the process alive with a process manager (PM2, systemd) or a container.
  • Put Nginx (or a load balancer) in front for HTTPS, compression and port 80/443; proxy to localhost:3000.
  • Set PORT to change the listening port.
pm2 start npm --name harmoni -- start
pm2 save

SSR means this cannot be a plain static-file host. You cannot upload .next/ to S3/Apache and expect it to work. A running Node.js process is required. (A static-only export would need output: 'export' and would remove SSR.)

10. Verifying SSR works

  1. Build output: npm run build should list / as ƒ (Dynamic).
  2. View source: in the browser press Cmd/Ctrl+U. The page text (e.g. "Engineering the AI Enterprise") should be in the raw HTML, not an empty <div>.
  3. curl: 
    curl -s localhost:3000 | grep "Engineering the AI Enterprise"
curl -sI localhost:3000 | grep -i cache-control
# → Cache-Control: private, no-cache, no-store, max-age=0, must-revalidate

Use npm run build && npm start for this check. In npm run dev everything renders on demand, so you cannot see the static-vs-dynamic difference.

Per-page title/SEOExport a metadata object (or generateMetadata) from that page.

Environment variablesCopy .env.example to .env.local. Only NEXT_PUBLIC_* variables reach the browser; all others stay server-only. (NEXT_PUBLIC_DRUPAL_API_URL is defined but not used yet.)

12. Gotchas and checklist

Common pitfalls

  • "window is not defined": browser APIs were used during render. Move them into useEffect or useSyncExternalStore.
  • Hydration mismatch warnings: server and client rendered different markup (e.g. branching on window.innerWidth during render). Follow the useIsMobile pattern.
  • NEXT_PUBLIC_* values are baked in at build time. Changing them requires a rebuild, not just a restart.
  • CSS import order matters: globals.css → custom.css → mobile.css in layout.jsx.
  • Turbopack root warning: the build may warn it picked /Users/<you> as the workspace root because of a stray package-lock.json in the home folder. Harmless; silence it by setting turbopack.root in next.config.mjs or removing that file.
  • Large public/ assets (18 MB of video/images) are served as-is. Put a CDN or Nginx cache in front for production traffic.
